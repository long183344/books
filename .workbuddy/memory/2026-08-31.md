### 关键工程经验(本次沉淀)
- **无 Java/PlantUML 本地**:使用公共 kroki.io (POST https://kroki.io/plantuml/{svg|png}, Content-Type: text/plain, body=源码) 渲染
- **Node fetch + Windows 路径**:`C:/...` 才能被 node 解析;`/c/Users/...` 会变成 `e:/c/Users/...` 找不到;Curl `--data-binary @file` 在此 shell 也不稳,统一用 Node + stdin body
- **kroki 输出尺寸硬上限** PNG 4096px(viewBox 4916→PNG 4096,自动等比缩 0.83)
- **`scale 0.x` 预处理器对 kroki 无效**(渲染结果与不加 scale 完全一致,SVG viewBox 不变)
- **mindmap 宽度由「一级分支数 × 每支最深叶节点文本长度」决定**:
  - 8 一级 + max depth 4 + 短文本(≤10字)→ viewBox 4916,可接受
  - 6 一级把硬件载体合并→ viewBox 6491 **更宽** 因为合并支变胖,反而变差
  - 结论:分支越多越窄,前提是每支本身瘦;不要为了减少分支数而把内容合并
- **`left side` 平衡**:4 左 + 4 右 比全右(或全左)窄一半左右,关键
- **font 10 + padding 3** 比默认 11 紧凑 ~30%

### 关键坑 & 修复（3 轮迭代）
- **第 1 轮**: 渲染出图, 但**斜向族子组框压在族标签上** (5 个斜向族全部受影响)
  - 原公式 `offset = LBL_H/2 + 0.25 + sub_w/2` 只考虑子组宽度做径向推进, 没考虑高度沿径向垂直方向也会与族标签相交
- **第 2 轮** `max(宽,高)/2`: 仍有重叠 (径向半长只保证径向不重叠, x/y 仍交叠)
- **第 3 轮正确公式** (采用):
  ```python
  sub_w = max(LBL_W, 0.20 * maxlen + 0.6)  # 限宽 ≤ 族标签
  th = 0.35
  need_dx = ((LBL_W + sub_w) / (2 * abs(dx))) if abs(dx) > th else 0
  need_dy = ((LBL_H + sub_h) / (2 * abs(dy))) if abs(dy) > th else 0
  offset = max(need_dx, need_dy) + 0.4
  ```
  - 含义: 沿径向推族+子组, 使两矩形在 x 和 y 两个轴上都不重叠
  - 阈值 th=0.35: |dx|<th 跳过 x 维度 (此时 sub_w ≤ LBL_W 保证 x 不重叠)
- **次要问题**: sub_w 必须 ≤ LBL_W, 否则正上/正下族子组 x 必覆盖族标签 (原 `LBL_W+0.4` 改 `LBL_W`)
- **figsize 增大** (36×26 → 52×44) 容纳推远的子组
- **Write 工具异常**: 长中文 content + markdown 表格触发参数序列化失败 (file_path undefined)
  - 改用 **bash heredoc** (`cat > file << 'ENDOFFILE' ... ENDOFFILE`) 成功写入 .md
