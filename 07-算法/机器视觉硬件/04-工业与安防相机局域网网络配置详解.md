# 工业与安防相机局域网网络配置详解（扩展版）

> **适用场景**：电脑 ↔ 交换机 ↔ 相机（纯内网封闭环境）
> **文档目的**：规范相机局域网的 IP 地址、子网掩码及网关配置，详解网卡"属性-高级"中与取流稳定性强相关的一批配置项，并提供标准故障排查流程。
> **配套说明**：本篇是「机器视觉硬件」系列第四篇——前作 01 工业相机详解、02 曝光增益帧率、03 镜头光源选型，本篇补齐"把相机接上网、稳定把图取回来"的最后一块拼图。

## 0. 拓扑与基本事实

```
[工业相机 ×N] ─┐
               ├──[工业/POE 交换机]──[工控机/电脑（采集卡或普通网卡）]
[工业相机 ×N] ─┘        （纯内网，不连互联网）
```

- 这是一条**纯二层内网**：相机、交换机、电脑三者物理直连/经交换，不经过路由器上公网。
- 取流（图像数据传输）走厂商私有协议（如海康 ISUP/ISAPI、大华、GigE Vision / RTSP / ONVIF），本质是 UDP/TCP 之上的大数据包流式传输。
- 决定取流质量的有三层：**物理层**（线缆/供电/端口）、**网络层**（IP/掩码/网关/MTU）、**主机侧**（网卡高级属性/防火墙/驱动）。

## 一、核心网络参数规划

### 1.1 参数设置黄金法则

| 参数 | 设置建议 | 核心说明 |
| --- | --- | --- |
| IP 地址 | 自定义（如 `3.168.1.x`） | 电脑与相机必须在**同一网段**，且 IP 不能冲突 |
| 子网掩码 | `255.255.255.0`（推荐） | 决定网络规模，两端设备必须保持一致 |
| 默认网关 | **留空（不填）** | 纯内网通信无需网关；填错网关会导致网络延迟或断连 |
| DNS 服务器 | **留空（不填）** | 内网设备无需域名解析 |

> **注**：`3.x.x.x` 理论上属于公网 IP 段，但在不连接互联网的封闭工业/安防内网中，常被作为私有地址使用，不会产生影响。若未来该网络要接公网，应改回 `192.168.x.x` / `10.x.x.x` / `172.16~31.x.x` 等 RFC1918 私有段。

### 1.2 子网掩码选择指南（/24 vs /16）

| 对比维度 | `255.255.255.0` (/24) ·首选推荐 | `255.255.0.0` (/16) ·特殊需求 |
| --- | --- | --- |
| 可用 IP 数量 | 254 个 | 65,534 个 |
| 通信范围 | 仅 `3.168.1.x` 互通 | `3.168.0.1 ~ 3.168.255.254` 全互通 |
| 广播域大小 | 小（网络负担轻，稳定性高） | 大（设备过多时易引发广播风暴） |
| 设备兼容性 | 几乎所有相机出厂默认支持 | 极少数老旧/低端相机固件可能不支持 |
| 适用场景 | 常规单机或多机直连（<254 台） | 需跨第三网段（如同时连 `3.168.1.x` 和 `3.168.2.x`）且无路由器 |

> ⚠️ **掩码配置警告**：若使用 `255.255.0.0`，必须确保电脑和相机的掩码**完全一致**。若一端为 /16、另一端为 /24，将导致**单向通信失败**（能 ping 通但无法取流）——因为 ARP/子网判断不一致。

## 二、操作系统配置步骤

### 2.1 Windows 系统

1. 按 `Win + R`，输入 `ncpa.cpl` 打开"网络连接"。
2. 右键点击连接相机的网卡 → **属性** → 双击 **Internet 协议版本 4 (TCP/IPv4)**。
3. 选择"使用下面的 IP 地址"，填写：
   - IP 地址：`3.168.1.10`（示例）
   - 子网掩码：`255.255.255.0`
   - 默认网关：**留空**
4. 点击"确定"保存。

> 多网卡机器（如同时有 WiFi 连外网 + 有线连相机）务必注意路由，见第四节 SOP ④。

### 2.2 macOS 系统

1. 进入 **系统设置 → 网络 → 选择对应网卡 → 详细信息**。
2. 在 **TCP/IP** 标签页，将"配置 IPv4"改为 **手动**。
3. 填写 IP 地址、子网掩码（`255.255.255.0`），路由器（网关）**留空**。
4. 点击"好"并应用。

## 三、网卡"属性-高级"关键配置项深度解析 ★

> **入口**：`ncpa.cpl` → 网卡 → 属性 → **配置** → **高级** 标签页。这里是一长串高级属性，**它们直接决定相机取流的稳定性、延迟与带宽利用率**。下面按"对取流影响从大到小"逐个解析。

### 3.1 巨型帧 Jumbo Frame / Jumbo Packet ⭐（最常被忽略的取流杀手）

- **是什么**：以太网标准 MTU 是 **1500 字节**；开启巨型帧后，单帧可承载 **4088 / 9014 字节**（常见选项 4088、9014、或"9KB MTU"）。
- **作用**：
  - 每个大数据包（一帧图像常被拆成多个包）需要的协议头（IP+UDP/TCP ≈ 42~54 字节）占比大幅下降，**有效带宽利用率提升**（1500 字节包开销约 3%，9014 字节包开销 <1%）。
  - 同等吞吐下 **CPU 中断次数减少**，主机更"省力"，高分辨率/高帧率取流时丢帧率显著下降。
- **配置方法**：高级 → 找到"巨型帧 / Jumbo Packet / Jumbo Frame"，设置为 `9014` 或 `9KB MTU` / 启用。
- **铁律（端到端一致）**：**网卡、交换机、相机三者 MTU 必须完全一致开启**。任何一端不开启或不一致，大包会被丢弃或分片，表现为"能 ping 通但一取流就丢帧/花屏"。
- **交换机前提**：中间交换机必须支持并启用巨型帧（管理型交换机在端口/全局开启；家用傻瓜交换机通常不支持）。
- **建议值**：GigE Vision / 高带宽工业相机场景**开启 9014**；千兆以下或不确定交换机支持时保持 1500 默认，先保连通再优化。

### 3.2 接收缓存帧 Receive Buffers（接收缓冲区）

- **是什么**：网卡驱动为**接收方向**预留的环形描述符缓冲区数量（不是字节，是"帧槽位"数量），典型范围 **128 ~ 2048**。
- **作用**：相机以突发方式高速吐数据（尤其高帧率）时，若主机 CPU 瞬间来不及搬移，数据先暂存在网卡缓冲区。**缓冲越大，吸收突发流量的能力越强，越不容易 buffer overrun 丢帧**。
- **配置**：高级 → "接收缓冲区 / Receive Buffers"，调大（如 512 / 1024 / 2048，依驱动选项）。
- **对相机的影响**：**多相机并发取流、高分辨率 8bit/10bit/12bit 大数据量**时，把接收缓存调大是最直接的防丢帧手段之一。
- **代价与注意**：仅消耗少量主机内存，**不影响带宽速率**；与巨型帧配合效果更佳。不是越大越好（极端值可能不稳），一般 512~1024 足够。

### 3.3 传送缓冲区 Transmit Buffers（发送缓冲区）

- **是什么**：发送方向的环形描述符缓冲区数量，机制同 3.2 但方向相反（主机 → 网络）。
- **作用**：平滑发送突发、提高发送效率，减少发送侧队列满导致的丢包。
- **配置**：高级 → "发送缓冲区 / Transmit Buffers"，默认即可；**发送量大的场景**（如软触发密集下发、参数频繁写相机、多路命令）可调大。
- **注意**：相机取流以"相机发、主机收"为主，**接收侧（3.2）远比发送侧关键**；发送侧一般保持默认即可。

### 3.4 环保节能 / Green Ethernet（建议：关闭）

- **是什么**：部分网卡芯片厂商的私有节能特性，根据**线缆长度**或**链路活动**动态降低发射功率/进入低功耗。
- **作用**：省电、降温、延长器件寿命。
- **对相机的危害**：链路空闲时降速/进入低功耗，当相机开始连续取流、数据突发到来时，PHY 需要从低功耗"唤醒"，**引入微秒~毫秒级唤醒延迟，表现为取流瞬间卡顿、首帧延迟、不规律丢帧**。
- **建议**：工业/安防实时取流场景**一律关闭**（Disabled / 关闭 环保以太网）。

### 3.5 节能以太网 EEE（Energy Efficient Ethernet, IEEE 802.3az）（建议：关闭）

- **是什么**：IEEE 标准化的链路节能机制。链路**空闲超过阈值**时进入 **LPI（Low Power Idle）** 低功耗状态，有数据再快速唤醒。
- **作用**：标准、通用的省电手段，对间歇流量的办公网络友好。
- **对相机的危害**：相机虽"连续取流"，但帧间仍有微空闲；EEE 周期性进入/退出 LPI 会引入**规律性微秒级延迟抖动**，在严格实时、高帧率场景下导致**不规律丢帧、时间戳抖动**。
- **建议**：实时取流、视觉检测产线场景**关闭 802.3az / EEE**（Disabled）。若仅做非实时录像/预览，可保持开启省电。

> **3.4 + 3.5 总结**：**实时性 > 节能**。工业相机网络把一切节能关掉，换来确定性的低延迟。

### 3.6 其它常见高级项速查

| 高级项 | 作用 | 相机场景建议 |
| --- | --- | --- |
| **流控制 Flow Control (802.3x)** | 接收方缓冲区将满时发 PAUSE 帧暂停对方发送，防拥塞丢包 | 开启（与交换机/相机协商一致），高带宽防丢包有效 |
| **中断节流 / Interrupt Moderation** | 合并中断降低 CPU 占用；调太高增加延迟 | 默认或"适中"；极高性能取流可略调低延迟优先 |
| **接收端缩放 RSS** | 多队列多核分发接收负载 | 多相机/多网卡/多核机器开启，分摊 CPU |
| **TCP/UDP 校验和卸载 Offload** | 网卡硬件算校验和，减轻 CPU | 一般开启 |
| **大型发送卸载 LSO / LRO** | 大段拆分/合并卸载到网卡 | 一般开启（但个别老旧驱动与相机协议冲突时可关） |
| **速度与双工 Speed & Duplex** | 强制 1Gbps/全双工 或 自动协商 | 关键链路**强制 1000Mbps/全双工**，避免自动协商降级到 100M 半双工 |
| **巨帧 Jumbo Packet** | 见 3.1 | 端到端一致开启 9014 |

### 3.7 高级属性配置总原则

1. **实时性 > 节能**：关掉 Green Ethernet、EEE(802.3az) 等一切节能。
2. **带宽吞吐**：开启巨型帧（端到端一致）+ 调大接收缓存帧。
3. **稳定性**：强制速率/双工、放行防火墙/关防火墙测试、必要时开流控制。
4. **改一项测一项**：每次只改一个高级项，ping + 实际取流验证，避免多变量无法定位。

## 四、连通性验证与故障排查

配置完成后，在电脑端打开命令行（CMD/Terminal），执行 `ping <相机IP>` 测试。

### 4.1 Ping 测试诊断

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| Ping 通且延迟 <1ms | 网络层正常 | 可直接打开相机客户端取流 |
| `Request timed out`（请求超时） | 物理层或网络层不通 | 进入下方排查流程 |
| `Destination host unreachable`（目标主机不可达） | IP 或掩码配置错误 | 检查两端是否在同一网段 |

### 4.2 标准排查清单 SOP

| 步骤 | 操作说明 |
| --- | --- |
| ① 检查物理连接 | 确认交换机通电，网卡和交换机对应端口指示灯亮起/闪烁；尝试更换网线或交换机端口 |
| ② 检查防火墙 | Windows 防火墙极易拦截相机协议；临时关闭防火墙测试，或在"高级安全"中放行相机软件入站/出站规则 |
| ③ 检查 IP 冲突 | 用厂商工具（海康 SADP、大华 ConfigTool、MVS 等）扫描局域网，确保没有两台设备同 IP |
| ④ 解决多网卡路由冲突 | 若电脑同时连外网(WiFi)和内网，路由可能混乱；以管理员运行 CMD 强制指定路由：`route add 3.168.1.0 mask 255.255.255.0 3.168.1.10 metric 1 -p` |
| ⑤ 开启巨型帧 | 部分工业相机传输大数据包需开启巨帧；网卡"高级属性"将"巨型帧/Jumbo Packet"设为 9KB 或启用（**交换机、相机同步开启**） |
| ⑥ 检查相机供电 | PoE 供电确认交换机支持 PoE 且功率达标；独立供电确认电源接通（很多故障实为相机未上电） |

> 取流仍丢帧但 ping 正常时，优先回到**第三节**：查巨型帧两端一致性、调大接收缓存帧、关闭节能。

## 五、常见误区 FAQ

- **Q1：我的 IP 是 `192.168.1.1`，掩码填什么？**
  A：标准家用/小型办公网络地址，掩码固定 `255.255.255.0`，网关通常填 `192.168.1.1`（路由器地址）。
- **Q2：为什么相机 IP 是 `169.254.x.x`？**
  A：这是 **APIPA（自动私有 IP）**。说明相机开了 DHCP 但局域网内没有 DHCP 服务器（如路由器）。请用厂商工具将其手动改为静态 IP（如 `3.168.1.x`）。
- **Q3：掩码填错了会烧毁设备吗？**
  A：不会。掩码填错只导致网络逻辑不通（无法 ping 通或取流），不造成物理损坏，重新配置即可恢复。
- **Q4：开了巨型帧反而取流更差？**
  A：几乎都是"端到端不一致"——交换机或相机没同步开。先确认三者 MTU 一致，再开。
- **Q5：节能选项关了能省电吗？**
  A：单张网卡省电微乎其微（瓦级），远不及取流稳定性收益；产线设备本就常开，无需纠结。

## 六、最佳实践速查表（配置清单）

| 项目 | 推荐配置 | 备注 |
| --- | --- | --- |
| IP / 掩码 / 网关 / DNS | 同网段静态 IP / 255.255.255.0 / 网关留空 / DNS 留空 | 两端掩码必须一致 |

| 速率/双工 | 强制 1000M 全双工 | 防协商降级 |
| 防火墙 | 放行或临时关闭测试 | 易拦截相机协议 |
| 多网卡 | 指定静态路由 | `route add ... -p` |
