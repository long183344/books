# 总线原理与分类

> **一句话结论**：总线的历史就是**「并行让位于串行」**的历史——不是因为串行更快，而是因为并行在高频下根本对不齐信号。
> **数据基准**：2026-08 ｜ **难度**：进阶 ｜ **前置**：[CPU 架构与工作原理](../CPU/01-CPU架构与工作原理.md)

---

## 1. 总线是什么

**总线 = 一组共享的传输通路 + 一套通信规则。** 它把 CPU、内存、外设连起来，让它们能交换数据。

任何总线都由三部分构成：

| 组成 | 作用 | 类比 |
| --- | --- | --- |
| **数据线** Data Bus | 传实际内容 | 货车装的货 |
| **地址线** Address Bus | 指明发给谁 / 从哪取 | 收货地址 |
| **控制线** Control Bus | 读还是写、什么时候有效、中断、仲裁 | 交通信号和调度 |

**地址线宽度决定寻址空间**：32 根地址线 → 2³² = 4 GB，这就是 32 位系统内存上限 4GB 的物理根源。

---

## 2. 并行 vs 串行：一次影响深远的反转

### 直觉是错的

早期思路很朴素：想快一点？多拉几根线并排送。于是有了 32 位 PCI、64 位 PCI-X、80 芯的 IDE 排线。

但频率一上去，并行就崩了：

| 问题 | 说明 |
| --- | --- |
| **时钟偏移 Clock Skew** | 32 根线长度差 1 mm，信号到达就差几十皮秒。频率越高，这个误差占周期的比例越大，最后接收端根本不知道该在哪个瞬间采样 |
| **串扰 Crosstalk** | 并排的线之间电磁耦合，互相干扰 |
| **信号完整性** | 高频下每根线都要做等长走线、阻抗匹配，PCB 层数和成本爆炸 |
| **引脚数量** | 64 位并行 = 至少 64 个引脚 + 地线，封装吃不消 |

### 串行的解法

```
并行：           串行差分：
──────┐         ──── D+ ┐
──────┤ 32根     ──── D- ┘ 一对（差分信号）
──────┤          
──────┘         · 无跨线偏移问题（只有一对）
需要严格等长      · 差分抗共模干扰
频率上不去        · 频率可以拉到几十 GHz
                 · 不够快？加通道（lane）横向扩展
```

**差分信号**：用两根线传一对反相电压，接收端取差值。外界干扰同时作用于两根线（共模），相减后抵消。这是所有现代高速接口（PCIe、USB、SATA、HDMI、DisplayPort、以太网）的共同基础。

**嵌入式时钟**：串行链路把时钟信息编进数据流里（靠 8b/10b、128b/130b、PAM4 + FEC 等编码保证足够的电平跳变），接收端用 CDR（时钟数据恢复）电路提取，从根本上消除了时钟线和数据线之间的偏移问题。

### 演进对照

| 并行时代 | → | 串行时代 | 换代时间 |
| --- | --- | --- | --- |
| ISA / PCI / PCI-X | → | **PCIe** | 2004 |
| IDE / PATA | → | **SATA** | 2003 |
| 并口 / SCSI | → | **USB / SAS** | 1996 / 2004 |
| FSB 前端总线 | → | **QPI / UPI / Infinity Fabric** | 2008 |

**唯一的例外是内存**：DDR 至今仍是并行的（64 位数据宽度）。原因是内存对**延迟**极度敏感，串行化需要的 SerDes 编解码会引入额外延迟。代价是 DDR5 走线要求极其苛刻，也是内存频率难以大幅提升的原因之一。

## 3. 三个核心指标

### 3.1 带宽（吞吐）

```
带宽 = 传输速率 × 通道数 × 编码效率
```

以 PCIe 5.0 ×16 为例：

```
32 GT/s × 16 lanes × (128/130 编码效率) ÷ 8 bit/byte ≈ 63 GB/s（单向）
```

> **GT/s ≠ Gbps**。GT/s 是「每秒多少次传输」，包含了编码开销；换算成有效数据要乘编码效率。这是规格表最容易被误读的地方。

### 3.2 延迟

从发出请求到收到数据的时间。**带宽靠堆通道能解决，延迟不能。**

| 层级 | 典型延迟 |
| --- | --- |
| 核内 L1 缓存 | ~1 ns |
| 跨核 L3 | ~15 ns |
| 本地 DDR5 内存 | ~70–100 ns |
| 跨 NUMA 节点内存 | ~130–180 ns |
| **CXL 挂载内存** | **~170–250 ns**（≈ 一次 NUMA 跳） |
| PCIe 设备 MMIO | ~500 ns – 1 μs |
| NVMe SSD | 20–80 μs |
| 局域网 | ~0.1–1 ms |

**残酷事实**：PCIe 从 Gen3 到 Gen7 带宽翻了 16 倍，延迟基本没变，甚至因为 FEC（前向纠错）和重定时器（Retimer）而略有增加。

### 3.3 缓存一致性

普通总线（PCIe）：设备和 CPU 各有各的内存视图，靠软件显式 DMA 搬运和刷缓存。
一致性总线（UPI、Infinity Fabric、CXL.cache）：硬件自动保证多方看到的数据一致。

这是 CXL 之所以重要的根本原因（详见 [前沿互连笔记](./03-前沿互连-CXL-UCIe-NVLink.md)）。

## 4. 按层级分类

```
┌─────────────────────────────────────────────────┐
│ ① 片内总线 On-chip                               │
│    AMD Infinity Fabric / Intel Ring & Mesh      │
│    ARM AMBA (AXI/CHI)                           │
│    连接：核心 ↔ 缓存 ↔ 内存控制器                 │
│    特点：延迟 ns 级，带宽 TB/s 级                 │
├─────────────────────────────────────────────────┤
│ ② 芯粒间总线 Die-to-Die                          │
│    UCIe / Infinity Fabric (IFOP) / Foveros      │
│    连接：Chiplet ↔ Chiplet（同一封装内）          │
│    特点：极高带宽密度，极低每比特能耗             │
├─────────────────────────────────────────────────┤
│ ③ 系统总线 System                                │
│    PCIe / CXL / DMI / UPI                       │
│    连接：CPU ↔ 显卡/SSD/网卡/芯片组               │
│    特点：可插拔、标准化、通用                     │
├─────────────────────────────────────────────────┤
│ ④ 外设总线 Peripheral                            │
│    USB / SATA / Thunderbolt / I²C / SPI         │
│    连接：主机 ↔ 外部设备                          │
│    特点：热插拔、长距离、供电能力                 │
└─────────────────────────────────────────────────┘
```

## 5. 拓扑结构

| 拓扑 | 结构 | 优点 | 缺点 | 实例 |
| --- | --- | --- | --- | --- |
| **共享总线** | 所有设备挂一条线 | 简单、便宜 | 需要仲裁，带宽被瓜分，扩展性差 | 老 PCI、I²C |
| **点对点** | 一对一专线 | 独占带宽，无仲裁 | 连接数受限于引脚 | PCIe 单链路、UPI |
| **交换式 Switch** | 中间加交换芯片 | 可扩展，并发通信 | 增加延迟和成本 | PCIe Switch、CXL Switch |
| **环形 Ring** | 首尾相连成环 | 布线规整，中等规模高效 | 跳数随节点数线性增长 | Intel 早期多核互连 |
| **网格 Mesh** | 二维网格 | 大规模下平均跳数低 | 面积和功耗高 | Intel 服务器 Mesh |
| **Fabric** | 可组合的交换网络 | 极致灵活，支持解耦 | 最复杂 | Infinity Fabric、CXL 3.0 Fabric |

**趋势**：核心数越多，越从 Ring 转向 Mesh / Fabric。Intel 服务器早在 Skylake-SP 就从 Ring 换成了 Mesh。

## 6. 常见误区

- ❌ **「并行一定比串行快」** → ✅ 在高频下正好相反。串行赢在能把单通道频率拉到极高，且可以横向堆通道。
- ❌ **「GT/s 就是 Gbps」** → ✅ GT/s 含编码开销。PCIe 3.0 的 8 GT/s 实际有效约 7.88 Gbps；PCIe 2.0 的 5 GT/s 因为 8b/10b 编码只有 4 Gbps。
- ❌ **「总线升级 = 全面变快」** → ✅ 只涨带宽。延迟敏感的负载（数据库、游戏）几乎感觉不到 Gen4→Gen5 的差别。
- ❌ **「PCIe 5.0 SSD 一定更快」** → ✅ 日常使用（游戏加载、开机）是**随机小文件 + 队列深度低**的场景，Gen5 相对 Gen4 提升极小，反而更热更费电。只有连续大文件读写才吃满带宽。
- ❌ **「内存也该串行化」** → ✅ 试过（FB-DIMM），失败了，因为延迟惩罚太大。CXL 内存是「补充」而非「替代」，用于扩容而不是替代本地 DDR。
